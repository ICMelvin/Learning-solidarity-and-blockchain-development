# How blockchain actually works
    ** A hash; is a unique fixed length string that identifies a peice of data {eg of hash algorithm includes(SHA256)}, to 
    create a hash, a peice of data is put into a hash function. ethereum uses (keccak-256 hash algorithm), the length of a 
    hash string length is constant no matter how big or small the data is. 

    ** {Went to a site called blockchain demo to discover the Difference btm hash, block, blockchain, distributed
    tokens, and coinbase}

    * Hash; had a fixed strict string length no matter how large the data is.
   
    * Block; also hashes data with a fixed string length but it has a unique number called (nonce) 
    that is used to mine each data with a given block number. a nonce is used by miners to solved a mathimatical
    computational problem in a blockchain, thus when they are mining they are looking for a particular nonce that 
    solved the computational problem they have or are given. the core Difference btm a Hash and a block is that a hash
    just hashes its given data but a block hashes with three Things(block no., nonce, and data)
   
    * Blockchain; is a collection of blocks but something is added to each block called (previous), this contains
    the hash of the previous block before that particular block. the first block in a blockchain is called the
    (Genesis block) and the previous hash it holds is non exsitent. thus this hashes data like a block but it now 
    also includes the hash from the previous block when hashing and if the previous block is altered the current
    and the ones after would be affected as well, this is what makes blockchains immutable.

    * Distributed(decentralized); distributes the same blockchain data and hash in peers/nodes that way each has a copy of
    the other peer block chain data and when a single blockchain decides to alter it's data, it would no longer 
    match that of the other peers hence invalid. in other words the list of transactions in a blockchain 
    is distributed in different inter-connected instances.

# Signing transactions

  ## A private key is only known by the holder and it's used to sign transactions.  the public key is the one 
  that everyone sees, it ususally used to verify that the transaction or data was signed by your private, thus 
  private and public keys comes in a pair. in a nutshell, a private key is to sign trasactions, while the public
  key is used to verify the signature, when you sign a transaction with your private key, you are then given a corresponding 
  hash called a massage signature, thus in order to verify a transaction you need a public key and the massage signature
  that was obtained during the signing of that transaction.
NB: your mnemonic key(seed phrase) + your account number or address gives you your private key.
    To create an address in the ethereum blockchain, you take the public key derived from the private key and 
    then hash it with the keccak256 hashing algorithm and then take the last 20 bytes.

# High Level Blockchain fundamentals
    * Blockchain is a decentralized database
    * Consensus is a mechanism used to agree on the state of a blockchain
    * Sybil Resistance is a way for a block to stop users from making fake ananymous blockchains 
    to influence a network
    * Layer 1 is the base layer blockchain solutions 
    * Layer 2 is any application built ontop of layer 1 blockchain that also benefits from the layer tight Security e.g(Chainlink, {arbitron and optmizim} => Rollups)

## Things to keep in mind concerning high level blockchain fundamentals
    * ETH & BTC are blockchains that uses proof of work(PoW), they follow nakamoto Consensus
    * ETH 2.0 uses proof of stake (PoS)
    * The bigger the blockchain the more secure it is.
    * Sharding and Rollups are the solutions to scalability issues in a blockchain 
    * Only so many transactios can fit into a block, the is the scalability problem that sharding solved.
    * Blockchain nodes keeps a list of transactions that occur {this way when the transaction is compared and if
    there is a node out of sync that node is deemed to be acting malicously and possibly punished or kicked out}
    * Consensus is the machanism used to agree on the state of a blockchain, this is brokedown into two which are

     ** Chain selection algorithm{
        - uses Consensus (which is the combination of the longest chain rule and proof of work {nakamoto Consensus})
     }
     ** Sybil resistance machanism{
        - Proof of work algorithm [PoW] {relies on computaional power}
        - Proof of Stake [PoS] {relies on owed capital}
     } 

    * proof of work [PoW] here miners race to solve the computaional problem while using high computaional hardwares, the first to solve the problem earns the reward.

    * proof of stake [PoS] here validators are chosen based on the number of coins they hold and are willingly to stake, and when they act dishonestly they are slashed
    of the coins they staked as collateral.

    * In prove of stake nodes are randomly chosen as authors to propose the new block and it's the job of the validators to 
    validate if the node has proposed the block honestly.

    * Sharded-blockchain is a blockchain that houses other blockhain
    * Rollups are layer 2 blochains that rollup their transactions into layer 1 e.g [arbitron and optimism]
    * A scalability problem in a blockchain is that a block can only hold a certain amount of transaction at a 
    given time which leads to very high gas prices.
    * Gas price is how much it costs to run a execution a blockchain.

# Asynchronous Programming in javascript

- Synchronous programs are programs that its code goes line by line, one after another, one task has to finish before the other begins
    -> Synchronous programs returns something called a promise, e.g {pending, fulfilled, rejected}, a promise is the status of the task being executed, Promise is a javascript method by the way.

- Asynchronous programs however executes other blocks or tasks while waiting for the first or already executing task to finish
    -> To make a function Asynchronous we add "async" before writing the function keyword for a particular function, and with an async function you can access the keyword "await" with tells the code to wait for that 
    line of code to complete execution before proceeding to the next.
